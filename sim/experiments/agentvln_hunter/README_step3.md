# AgentVLN 第 3 步：局部深度定位与停靠

本文件记录"经过红牌，在两个蓝箱中较远的那个前方停下"这条指令在 HUNTER 仿真里的
闭环实现、三次重复结果、失败样例和复现命令。全部运动由固定基线 Nav2 执行
（`nav2_params_fix.yaml`、AMCL、DUBIN、最小转弯半径 1.669 m、不允许倒车）。

## 2. 闭环流程

`tools/step3_pipeline.py` 一次跑完下列阶段，全部写入 `report.json`：

1. **初始观察**：同步取一帧 RGB+深度（时间戳与 /clock 的差 ≤1.5 s，且 map→光学 TF 可用）。
   spawn 处只能看到 1 个蓝色连通域（另一箱在视野外），记录后进入再观察。
2. **再观察（纠偏）**：按 `observation_route` 用 Nav2 `NavigateToPose` 逐段开到
   `(2.00, 0.50, 0.522)`，每段结束重新取图。到点后两箱分离（图 3）。
3. **深度查询**：对每个连通域取 25×25 邻域，用有效像素中值估计光轴深度，回传
   测量值、单位 m、有效像素数与占比；保留查询前的按面积选择记录和查询后的按深度
   选择记录。
4. **反投影**：`p_camera = z·K⁻¹·[u,v,1]ᵀ`，用同一帧时间戳的 map←光学 TF 变到地图。
5. **停靠位姿生成**：在"机器人→测量点"射线上后退 `0.934+backoff` m，朝向取射线方向
   （直进停靠），按车身轮廓与已知箱体矩形做净空剔除，再用 `ComputePathToPose` 试规划。
6. **执行与纠偏**：`NavigateToPose` 执行；失败则按当前 AMCL 位姿重算直进停靠点重试，
   最多 3 次（实测三次成功运行都只用 1 次）。
7. **独立验收**：真值位姿到停车区圆心 ≤0.30 m、朝向误差 ≤0.50 rad、停稳位移 ≤0.05 m，
   同时要求动作 status=4。

关闭主动深度查询时，最终反投影仍使用同一帧深度（按计划要求保留），只有"选哪只箱"
退化为像面积代理。在本场景两种判据恰好选中同一只箱（近箱 2.17–2.22 m / 远箱
2.99–3.11 m，远箱像面积只有近箱的 47–53%），因此这一次对照只证明"去掉主动查询
不会破坏闭环"，不证明判据等价；要观察判据分歧需要构造近箱被部分遮挡的帧。

## 6. 已知限制

- **没有 VLM**。目标检测是 HSV 蓝色阈值 + 连通域，属于工程基线；本地无可用的
  VLM 推理后端（见 README_step2.md §5）。指令文本只作为报告字段，不参与决策。
- **红牌是悬空牌面**（z 0.90–1.20，无立柱）。GPU 激光是渲染传感器，会看见只有
  visual 的几何；落地立柱会进代价地图并堵死再观察路线。牌面高度取在激光平面
  （世界 z = 0.165+0.62 = 0.785 m）之上 0.11 m。
- **停靠朝向是斜的**。车的最小转弯半径 1.669 m、不能倒车也不能原地转，最后一段
  必须是直线；因此停靠朝向等于"观察位姿→目标"的方位角（约 0.42 rad），车头指向
  目标但车身与箱面法向差约 25°。
- **停车区是独立标注的真值判据**，不参与决策；半径 0.30 m 里包含了 Nav2
  `xy_goal_tolerance` 0.20 m 的到点残差。
- **碰撞未测**。Gazebo Fortress 的 contact 话题在本机构建里从不广播（见 README.md
  §7），只用轮廓净空与停车区距离做代理，接触事件标 `not_measured`。
