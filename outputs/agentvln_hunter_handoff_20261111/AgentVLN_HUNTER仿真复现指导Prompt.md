# AgentVLN 在 HUNTER 2.0 仿真中的方法复现 Prompt

请在 `D:/rob-memory` 接手我的 HUNTER 2.0 仿真项目。目标是用一句包含地标、顺序和停靠关系的指令，让虚拟车从第一视角认路、选择可达路点，并在看到目标后用深度确定停靠位置。复用现有 Nav2 执行每段运动。按下面顺序实际运行，逐阶段保存证据。

## 复现范围

| 论文部分 | 在 HUNTER 上的落地方式 |
| --- | --- |
| §3.1–3.2 的 VLM-as-Brain | 单个视觉语言 Agent 根据图像和指令调用感知、选路、到点与停止技能。底层复用 Nav2。 |
| §3.3 的跨空间映射 | 用已验证的实验室地图产生可达候选，把地面路点投影到车头 RGB 图中，由 Agent 从编号候选中选路。首轮用固定地图替代论文的在线增量探索图。 |
| §3.3 的遮挡与纠偏 | 看不到相关地标时，换到一个可达的近处观察点，重新取图并继续任务。用 HUNTER 能开到的位姿替代原论文的离散左右转动作。 |
| §3.4 的局部定位与 QD-PCoT | 目标可见后，按需查询指定图像区域的深度，消解近远歧义，再把目标像素反投影到地图坐标，规划到目标附近的可停靠位姿。 |
| §4.5 的对照实验 | 在同一批任务上逐个开关画面路点标注、按需深度查询和纠偏，观察成功率、终点误差和路径变化。 |

本轮交付是**在已知实验室地图上复现方法机制**。Habitat 的 R2R-CE / RxR-CE 原榜单、全量指令微调及 Go2 / Jetson 部署另立任务。作者已发布训练、推理和数据生成代码，查阅时 README 仍把预训练检查点列在待办，数据卡也把 QD-PCoT 部分列为待公开。先用可验证的本地感知与推理后端做实验，记录实际模型来源。 [论文 §3–4](https://arxiv.org/html/2603.17670v1) · [作者仓库](https://github.com/Allenxinn/AgentVLN) · [数据卡](https://huggingface.co/datasets/allenxinn/AgentVLN-Instruct)

## 1. 固定导航基线，接通同一辆车的相机

- 在 Windows 台式机的 WSL Ubuntu 22.04 / ROS 2 Humble / Gazebo Fortress 内操作。虚拟车运动前说明是仿真，核对 ROS 域 73、`ROS_LOCALHOST_ONLY=1`、CycloneDDS、独立 Gazebo 分区及仿真桥接方向。全程限仿真，不连接实车域 88。
- 复用 `D:/rob-memory/sim/experiments/lab_nav_fix_20261106/run_fix_stack.bash` 及同目录的 `stop_fix_stack.bash`、`run_nav_eval_fix.py`。本实验用 `PARAMS` 指向同目录 `nav2_params_fix.yaml`（前进策略、未知区不可通行、最小转弯半径约 1.67 m），用 `LOCALIZER=amcl`。入口默认是 `nav2_params_carmatch.yaml`，启动后读回实际参数，并核对地图为 `D:/rob-memory/outputs/lab_nav_fix_20261106/lab_nav_map_fix.yaml`。先用已知坐标目标复测到点、取消和停稳。
- `D:/rob-memory/outputs/lab_nav_20261105/lab_nav_world_drive.sdf` 目前只有二维激光。在该世界和桥接的副本里，参考 `D:/rob-memory/sim/scenes/hz_hunter_full.sdf` 和 `D:/rob-memory/sim/config/hunter_full_bridge.yaml` 移植已验证的 RGB-D 相机及其光学 TF，增加 RGB、深度、CameraInfo 的 Gazebo→ROS 桥。利用现有入口的 `WORLD`、`BRIDGE`、`LOG_DIR` 指向实验副本。
- 验收同一仿真会话里 Nav2 可用、RGB 和深度能同步采样，图像尺寸、深度单位、内参和光学 TF 相符，静止与行驶中都有新帧。用几个已知距离和角度的标记点核对投影、测距和反投影，保存原图、标注图、误差及消息时间戳。相机用现有仿真内参近似，具体来源见 `D:/rob-memory/outputs/hunter_sensor_parameters_20261030/README.md`。

## 2. 做出图像选路和到点技能

- 在场景副本放墙牌或有辨识度的道具，先覆盖一段直道和一个车能通过的转弯。候选从无语义的自由空间生成，按车身轮廓、转弯半径、姿态和 Nav2 试规划筛选。用图像时刻的 TF 把候选变到相机光学坐标，再用 CameraInfo 按 `u=fx·X/Z+cx`、`v=fy·Y/Z+cy` 投到 RGB。剔除相机后方、画面外和被遮挡的点，叠加编号。
- Agent 输入指令、当前图像、候选编号及最近观察和动作结果。允许它用结构化输出选择当前候选、查询深度、指定目标图像区域、请求再观察或结束。执行器校验编号和帧是否有效，从候选取实际位姿，先试规划，再用 Nav2 的 `NavigateToPose` 一次执行一段。每段结束后取新图并更新任务进度。
- 先用录制画面和人工或规则选择验证接口，再接实际读取图像的本地 VLM。台式机识别到 AMD Radeon RX 9070 XT，WSL 推理后端需实测。有兼容后端可先试作者所用基础模型的指令版，验收单张图像、编号选择和结构化输出，再接实时链路。模型暂不可用时，先用颜色或标志检测跑通闭环，结果标为工程基线。 [Qwen2.5-VL-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)

## 3. 加入局部深度定位和纠偏

- 用“经过红牌，在两个蓝箱中较远的那个前方停下”这类指令。目标未见时按路点推进，识别到目标后切到局部定位。让 Agent 对两个目标区域主动调用深度工具。工具用同帧有效像素的中值估计深度，回传测量值、单位和有效像素占比。保留查询前后的选择记录。
- 对选中区域的有效像素，确认光轴深度后用 `p_camera = z·K⁻¹·[u,v,1]ᵀ` 反投影，再用同一时刻 TF 变到地图。由几何模块生成满足指令距离和车体净空的地面停靠位姿，试规划后执行。用场景标注的停车区独立验收。处理无效深度、遮挡及过期观测。
- 遇到无有效候选、暂时遮挡或动作失败，最多尝试预设次数的短程可达观察位姿，再决定继续或安全结束。不给模型直接发速度的权限。用“先挡住目标、绕过可行转角后才能看见”的用例记录一次恢复，并做关闭纠偏的对照。超时同时看仿真时间和墙钟，取消须等动作终态并确认停稳。

## 4. 验收与交付

- 先用每类一个任务做冒烟，再固定至少 6 个任务，覆盖单地标、带顺序的转弯、目标歧义或遮挡，每个任务至少重复 3 次。记录地图和场景版本、初始位姿、指令、场景布置、随机种子、模型版本与预算。交换地标位置或近远关系，保持指令不变，验证选择会随画面改变。目标坐标和 Gazebo 真值只供已知坐标基线与独立评测。
- 用同一批任务比较已知坐标的 Nav2 基线与视觉语言闭环。做配对对照时只改一项。关掉画面编号时仍提供相同候选的文字像素坐标。关掉主动深度查询时保留最终反投影。关闭纠偏时保持总预算相同。先在相关任务子集完成各项对照。
- 成功要求依次经过指定区域、到达独立标注的停车区并停稳。测试前冻结位置和必要的朝向容差。记录成功率、终点误差、真值路径长度、耗时、模型调用与纠偏次数。若有同样约束下的可达最短参考路径，再计算实验室 SPL。接触事件若仍无有效数据就标 `not_measured`，另报轮廓净空或重叠代理。
