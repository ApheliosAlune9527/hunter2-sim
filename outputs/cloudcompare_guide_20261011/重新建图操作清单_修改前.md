# 重新建图操作清单

适用：car-NUC15JNKU7X4，ROS 2 Humble，个人工程 /home/car/hz_ws，XT32 + CH104 + D435i。

以下全部命令在小车 Ubuntu 上执行。按顺序逐条运行，上一条正常结束再执行下一条；出现报错时停在该步，保留输出。程序持续运行的终端需要保持打开。

新地图、配置和日志放在个人工程中；每轮使用新的地图目录，旧地图保留。底盘沿用原有上电和手持遥控方式。

先打开小车及传感器电源，确认设备接好、当前无人使用小车。实际移动前拔掉充电线，并准备好手持遥控器。

打开六个终端，按下面的用途分配。终端 A 从开始到结束都保留，后续的本轮路径变量只在 A 中使用。

| 终端 | 用途 |
| --- | --- |
| A | 准备、检查数据、监测、停止、保存和查看 |
| B | XT32 雷达 |
| C | CH104 IMU |
| D | D435i 相机 |
| E | FAST-LIVO2 建图 |
| F | RViz 实时显示 |

代码中以 # 开头的行是说明，不是需要单独执行的操作。

1. **终端 A：停止旧会话，准备新一轮。**

    ```bash
    # 查看个人建图会话是否还有程序运行；输出 {} 表示没有匹配到运行程序
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py status

    # 有序停止个人会话的传感器、RViz 和建图程序
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py stop

    # 检查设备占用和磁盘，创建本轮新目录及配置，准备自动分批保存
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py prepare
    ```

    看到“新一轮目录”和“保存设置：interval=1”后继续。prepare 每轮只执行一次。

    ```bash
    # 自动把本轮目录记在 hzRun 变量中，不需要手工输入日期和时间
    hzRun=$(python3 -B -c 'import json; print(json.load(open("/home/car/hz_ws/maps/hz_active_session.json"))["run_dir"])')

    # 显示刚刚记住的目录，后面所有 "$hzRun/..." 都指向这一轮
    echo "$hzRun"
    ```

    应显示类似 /home/car/hz_ws/maps/lab_日期_时间 的路径。保持终端 A 打开。

2. **终端 A：加载检查命令需要的 ROS 环境。**

    ```bash
    # 加载 ROS 2 Humble，让当前终端能够使用 ros2 命令
    source /opt/ros/humble/setup.bash

    # 加载现有 D435i 驱动环境
    source /home/car/d435i_ws/install/local_setup.bash

    # 加载个人工程环境
    source /home/car/hz_ws/install/local_setup.bash

    # 使用此前建图时的 ROS 通信分组
    export ROS_DOMAIN_ID=88

    # 使用此前验证过的通信设置
    export RMW_IMPLEMENTATION=rmw_fastrtps_cpp ROS_LOCALHOST_ONLY=0

    # 将 ROS 日志和生成的缓存放在个人目录，并禁止 Python 生成字节码缓存
    export ROS_HOME=/home/car/hz_ws/.ros ROS_LOG_DIR=/home/car/hz_ws/logs/ros PYTHONDONTWRITEBYTECODE=1
    ```

    这些设置只影响当前终端。B～F 的启动助手会自动加载它们需要的环境。

3. **分别启动三个传感器。**

    终端 B：

    ```bash
    # 启动 XT32 雷达，向 /lidar_points 发送点云
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py lidar
    ```

    终端 C：

    ```bash
    # 启动 CH104 IMU，向 /imu/data 发送惯性数据
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py imu
    ```

    终端 D：

    ```bash
    # 启动 D435i 彩色相机，使用 640×480、15 Hz 的图像
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py camera
    ```

    B、C、D 都保持打开。只显示启动提示、没有持续刷屏是正常的，详细输出写在本轮日志中。

4. **终端 A：确认三个传感器有数据。**

    传感器启动后先等约 10 秒，再逐条执行：

    ```bash
    # 测量雷达接收频率，期望约 10 Hz；约 8 秒后自动结束这次检查
    timeout -s INT -k 2s 8s ros2 topic hz /lidar_points

    # 测量 CH104 接收频率，期望约 100 Hz；约 8 秒后自动结束这次检查
    timeout -s INT -k 2s 8s ros2 topic hz /imu/data

    # 测量彩色图像接收频率，期望约 15 Hz；约 8 秒后自动结束这次检查
    timeout -s INT -k 2s 8s ros2 topic hz /camera/camera/color/image_raw
    ```

    看输出中的 average rate。Hz 表示每秒收到多少份数据；数值可以波动，也会受电脑负载影响。三个话题都收到数据再继续；一直没有频率输出时，先保留终端并回传结果。[ROS 2 频率检查说明](https://github.com/ros2/ros2_documentation/blob/humble/source/Tutorials/Beginner-CLI-Tools/Understanding-ROS2-Topics/Understanding-ROS2-Topics.rst)

5. **终端 E：启动建图。**

    ```bash
    # 启动个人 FAST-LIVO2，融合雷达、CH104 和相机数据，并自动保存点云分块
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py mapping
    ```

    E 保持打开。小车先静止约 30 秒，等待初始化。

    回到终端 A：

    ```bash
    # 读取保存间隔，正常应输出 Integer value is: 1
    ros2 param get /laserMapping pcd_save.interval

    # 查看最新 20 行建图日志，了解初始化和运行情况
    tail -n 20 "$hzRun/mapping.log"
    ```

    param get 只读取参数。[ROS 2 参数读取说明](https://github.com/ros2/ros2_documentation/blob/humble/source/Tutorials/Beginner-CLI-Tools/Understanding-ROS2-Parameters/Understanding-ROS2-Parameters.rst)

6. **终端 F：打开 RViz 看实时建图。**

    ```bash
    # 打开 RViz，并自动加载个人工程的显示配置
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py rviz
    ```

    F 保持打开。RViz 的 Fixed Frame 应为 camera_init。彩色点云显示最近约 5 秒的数据，更早的点云已另行写入文件。RViz 的 Save 按钮保存的是显示配置，地图由建图程序自动保存。

7. **终端 A：开启运行监测。**

    ```bash
    # 每 5 秒显示可用内存、磁盘空间、已保存 PCD 数量和建图程序编号
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py watch
    ```

    看到建图 PID 是一个数字、已落盘 PCD 数量大于 0 且持续增加，才开始移动。A 会持续显示监测信息，保持打开。

    watch 在建图程序消失、可用内存不足 4 GiB 或磁盘不足 2 GiB 时会停止本轮采集。看到停止提示后，仍需用遥控器让车停稳。

8. **用手持遥控器采集地图。**

    这一段不用输入命令。拔掉充电线后，用遥控器低速、平稳地绕行，转弯减速，从不同方向观察墙面和桌椅。先做约 3～5 分钟的短轮，留意终端 A 的状态。结束时尽量回到起点及相同朝向，然后停车。

9. **终端 A：停止采集，检查并打包。**

    先用遥控器让车完全停稳。在终端 A 按一次 Ctrl+C，退出 watch 监测。如果 watch 已提示自动停止且正在等待退出，等它结束后再继续。

    ```bash
    # 有序停止传感器、RViz 和建图程序；等待“相关进程已退出”
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py stop

    # 检查本轮所有编号 PCD 的完整性，并统计点数
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py check

    # 把点云、配置和日志打包，计算校验值，记录本轮导出位置
    python3 -B /home/car/hz_ws/scripts/hz_mapping_session.py pack
    ```

    check 应显示“结构检查通过”，点数大于 0。pack 完成后会打印归档路径；逐条成功后再继续。数据完整性检查用于发现文件缺失或截断，地图的几何质量还需要查看和现场比较。

10. **终端 A：合并并查看本轮地图。**

    ```bash
    # 将本轮分块合并成完整地图，同时生成 15 cm 抽稀预览；写入本轮的新子目录
    python3 -B /home/car/hz_ws/scripts/pcd_export.py merge "$hzRun/pcd" "$hzRun/merged_for_view"

    # 列出生成的两份地图，查看文件名称和大小
    ls -lh "$hzRun/merged_for_view/"
    ```

    生成的 map_raw.pcd 保留本轮全部原始点；map_preview_015m.pcd 用于较轻的查看。分块、日志和 tar.gz 归档也保留。

    ```bash
    # 打开轻量预览，先看房间全貌；-ps 3 将显示的点放大
    pcl_viewer "$hzRun/merged_for_view/map_preview_015m.pcd" -ps 3
    ```

    需要看完整细节时，先关闭预览窗口，再在 A 执行：

    ```bash
    # 打开完整地图；-ps 1 用较小的显示点尺寸
    pcl_viewer "$hzRun/merged_for_view/map_raw.pcd" -ps 1
    ```

    用鼠标左键拖动旋转、滚轮缩放。关闭查看窗口后，即可关闭终端并按实验室原有方式收车。

下一次建图从第 1 步重新开始，让 prepare 创建新的运行目录。已经写出 PCD 的一轮不要直接重启 mapping；需要重来时先停止并保存，再准备新一轮。
