## 仿真变更与静态复测

- 完整模型主场景 IMU 设置由 50 Hz 调整为 100 Hz，场景检查器同步更新；重建场景并更新严格校验清单。逐字节对比确认场景中仅 IMU 更新频率改变，GUI 及场景清单其他字段不变。相机、雷达、坐标关系、原始模型源文件均未重新标定或改写。
- 静态复测记录：[成功结果](../hunter_research_platform_20261031/sensor_trials/568b77c51860/check.json)。模型均静止，车体控制插件移除，测试使用本机 ROS 域 74 和独立 Gazebo 分区；桥接仍为 Gazebo → ROS。IMU、雷达、RGB、深度、二维扫描和 TF 均有数据且检查通过；速度指令发布者为 0。
- 该次 ROS 观察到 100 条 IMU 消息，首尾仿真时间 0.002～0.990 秒，按消息时间戳计算约 **100.20 Hz**；相邻消息的仿真时间间隔为 8～10 ms。按接收时的真实时间计算约 **13.81 条/秒**。也就是说，该次完整传感器静态场景约以 0.14 倍真实时间运行；它不证明达到实时运行，具体耗时来源和其他场景的表现仍需分析。
- 做了一次[仅保留 IMU 的静止对照](imu_only_trials/5f7b6c605ee1/check.json)：移除相机、雷达和渲染传感器系统，只桥接 IMU，301 条消息对应约 100.07 Hz 仿真时间、100.02 条/真实秒，实时系数约 1.00。两次实验的传感器及 ROS 观察负载不同，结果提示完整传感器链的额外负载与减速有关，但不能据此断定具体瓶颈或量化单一传感器成本。
- 实验室场景下的 `lab_scene_with_vehicle*.sdf` 是此前的静态放置/复位历史快照，保留原有 50 Hz 字段且其中 IMU 系统插件被移除；它们不是本次 100 Hz 传感器验收场景。之后应从更新后的主场景生成新的实验室运行场景，并重新验证传感器。
