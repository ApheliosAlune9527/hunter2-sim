HUNTER 2.0 仿真导航入门教程（2026-11-06 实测版）
============================================

这份教程带你亲手在仿真里走一遍：启动场景 → 看地图和扫描 → 定位 → 发目标 →
取消 → 确认停车 → 退出。每一步只给一条命令，都说明"在哪个终端、为什么、应该看到什么"。

所有命令都在 2026-11-06 这台机器的仿真环境里实跑过。命令里出现的路径可以原样复制。

--------------------------------------------------------------------
一、先弄清三个名词（不然看不懂后面）
--------------------------------------------------------------------

Gazebo（仿真器）
  在电脑里造一个假世界：墙壁、地面、车。它按物理规律算车轮怎么转、车怎么走。

ROS 2（机器人软件框架）
  真实机器人上的一堆程序靠它互相说话：定位程序、规划程序、控制程序……

桥接（bridge）
  Gazebo 和 ROS 2 各自有一套"说话方式"，互相看不见。桥接程序把指定消息在两边
  抄一遍：仿真里的扫描 → ROS 的 /scan，ROS 的 /cmd_vel → 仿真里的速度指令。
  这就是为什么启动脚本里要单独起一个 bridge 进程。

话题（topic）
  一个名字下不断流动的消息。本例里最重要的几个：
    /scan          激光扫描一圈的距离
    /odom          轮子算出来的里程计（车自己以为走了多远）
    /ground_truth  仿真给的绝对真实位姿（只有仿真有，实车没有）
    /cmd_vel       速度指令，谁发到这里谁就在开车
    /map           地图（一格一格的占用/空闲/未知）

--------------------------------------------------------------------
二、启动仿真场景
--------------------------------------------------------------------

终端：Windows 的 PowerShell（不是 WSL 里）。

  wsl.exe -d Ubuntu-22.04 -u aphelios -- env GUI=1 STAGE=sim bash /mnt/d/rob-memory/sim/experiments/lab_nav_fix_20261106/run_fix_stack.bash

这条命令做了四件事：进 WSL → 用 aphelios 身份 → 设 GUI=1（开窗口）、STAGE=sim
（只起场景和桥接，不起导航）→ 跑启动脚本。

应该看到：

  [stack] world sha256=1100cd59...
  [stack] gui=on
  [stack] server pid=...
  [stack] bridge pid=...
  [stack] scene and bridge ready (stage=sim)

并弹出一个 Gazebo 窗口：一个长条房间（白色墙体）、灰色地面、房间里有一台小车。
右侧 Entity 树应该有 floor / walls / hz_hunter_full / sun 四项。

如果看到 "refusing to start: these recorded processes are still alive"，说明上一次
没关干净，按提示先跑停止脚本（见第七节）。

--------------------------------------------------------------------
三、进 WSL，加载环境
--------------------------------------------------------------------

终端：另开一个 WSL 窗口（或者上面的 PowerShell 里输 wsl 也行）。

  wsl.exe -d Ubuntu-22.04 -u aphelios

提示符会变成 aphelios@机器名:... 。

  注意：加载环境必须单独一条命令，不要和别的命令写在同一行。

  source /mnt/d/rob-memory/sim/experiments/lab_nav_fix_20261106/lab_nav_fix_env.bash

应该看到：

  已加载个人仿真环境：Humble / ROS 域 73 / 本机通信 / Radeon RX 9070 XT。

"域 73"很重要：仿真用 73，实车用 88，两个域互相看不见，防止误把仿真指令发到真车上。

--------------------------------------------------------------------
四、看话题：ROS 到底看见什么
--------------------------------------------------------------------

  ros2 topic list

应该出现 9 个，其中至少包括：/clock /cmd_vel /joint_states /odom /scan /ground_truth。

  /scan 有数据，说明桥接把激光转过来了；没有 /scan 就是桥接没起来。

再看扫描是不是只有一个来源（防止重复发布）：

  ros2 topic info /scan

应该看到 Publisher count: 1。

看频率：

  ros2 topic hz /scan

应该是 10 左右（10 Hz 是雷达的设定频率）。如果看到 20，说明有两个桥接在同时发，
必须停下来查（本机就踩过这个坑）。

--------------------------------------------------------------------
五、起完整栈（定位 + 导航 + RViz）
--------------------------------------------------------------------

先停掉刚才的场景：

  bash /mnt/d/rob-memory/sim/experiments/lab_nav_fix_20261106/stop_fix_stack.bash

应该看到 [stop] stopped=2 skipped=0 still_alive=0。

再起完整栈（回到 PowerShell）：

  wsl.exe -d Ubuntu-22.04 -u aphelios -- env GUI=1 bash /mnt/d/rob-memory/sim/experiments/lab_nav_fix_20261106/run_fix_stack.bash

这次会多起 truth（真值定位）、nav2（导航）、rviz（可视化）三个进程，
并打开 Gazebo 和 RViz 两个窗口。

RViz 里应该看到：
  黑白的墙（地图）、青色带（代价地图的膨胀区）、绿色细框（车体轮廓）、
  红色小点（当前扫描）。

--------------------------------------------------------------------
六、确认定位，然后发目标
--------------------------------------------------------------------

终端：WSL 窗口。

  ros2 run tf2_ros tf2_echo map base_link

应该每秒打印一行 Translation: [-0.210, -0.770, 0.000]——这就是车在地图里的位置。
（开头可能报一次 Invalid frame ID "map"，那是第一条消息还没到，正常。）

发一个正前方 2.4 米的目标：

  ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{pose: {header: {frame_id: map}, pose: {position: {x: 2.2, y: -0.77, z: 0.0}, orientation: {w: 1.0}}}}"

应该看到 Goal accepted with ID: ...，然后车往前开，最后
Goal finished with status: SUCCEEDED。

注意：车会停在离目标十几厘米的地方。控制器参数 xy_goal_tolerance 是 0.20 米，
进了这个圈就算到达，这是正常的，不是失败。

几种状态的意思：
  SUCCEEDED  做到了
  ABORTED    做不到（常见原因：目标太靠近墙、路径被挡、控制器判定要撞）
  CANCELED   被叫停

--------------------------------------------------------------------
七、取消与停车
--------------------------------------------------------------------

发一个更远的目标，并在车开动 3 秒后按 Ctrl+C：

  ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{pose: {header: {frame_id: map}, pose: {position: {x: 3.6, y: -0.77, z: 0.0}, orientation: {w: 1.0}}}}" --feedback

Ctrl+C 之后应该看到 Goal finished with status: CANCELED，车立刻停住。

然后确认它真的停了（不是惯性滑行）：

  ros2 topic echo /odom --field twist.twist.linear.x

每行都应该是 0.0。按 Ctrl+C 退出这条命令。

如果这里看到 0.1、0.2 这样的非零值，说明还有别的程序在发 /cmd_vel，
立刻用下面的停止脚本，别等它自己停。

--------------------------------------------------------------------
八、安全退出
--------------------------------------------------------------------

  bash /mnt/d/rob-memory/sim/experiments/lab_nav_fix_20261106/stop_fix_stack.bash

应该看到 [stop] stopped=5 skipped=0 still_alive=0。

  注意：直接关窗口不等于停进程。启动脚本用 setsid 把进程放到独立会话里，
  关窗口只是关掉了显示，进程还在后台跑，并且会占着话题和节点名，
  导致下一次启动被守卫拦下。

skipped 不是 0 时，脚本会说明是哪一条、为什么跳过（通常是那个 pid 已经被别的
进程复用，脚本拒绝误杀）。这种情况按它打印的命令再跑一次。

--------------------------------------------------------------------
九、常见问题
--------------------------------------------------------------------

问：ros2 topic list 是空的，或者报 Could not determine the type？
答：ROS 的守护进程过期了。跑 ros2 daemon stop，再重试。

问：车在原地不动，但里程计在涨？
答：轮子在转、车身却被挡住。多半是车被放进了墙里，或者模型和地图对不上。
    用 ros2 run tf2_ros tf2_echo map base_link 看真实位置是不是在地图的白色区域。

问：目标明明看得见，却一直 ABORTED？
答：这个车最小转弯半径 1.669 米、不能倒车、不能原地转。目标在侧面很近距离时
    根本转不过去。另外目标离墙太近时，控制器会因为"再往前要撞"而拒绝最后几十厘米。
    先把目标选在正前方 2–3 米处。

问：扫描里全是 0.1？
答：0.1 是传感器最小量程，说明雷达被自己的外壳挡住了，或者桥接把扫描转坏了。
    本机的雷达装在 0.62 米高度就是为了避开外壳。

--------------------------------------------------------------------
十、这套东西现在能做什么、不能做什么
--------------------------------------------------------------------

能：地图加载、真值定位、规划、避障代价地图、低速到点、取消、停车、正常退出。
不能（还没测或已知缺失）：
  · 碰撞事件统计（场景里没有可用的接触传感器数据）
  · 真实里程计的长期漂移
  · AMCL 定位在新轮廓上的精度
  · 批量评测

写报告时请把"通过"和"未测"分开，不要把没测过的写成 0。
