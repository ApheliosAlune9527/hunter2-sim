# Go2 EDU：中文说明书核对与科研路线补充

整理日期：2026 年 11 月 10 日。依据：用户提供的《Unitree Go2 EDU 使用说明书》PDF、宇树官方中文用户手册、SDK2 / ROS 2 / RL 仓库，以及此前围绕导航、多 Agent VLN 和强化学习的调研。

**本次没有连接、检查或控制 Go2 实机。**本文件区分“说明书写了什么”“官方当前代码支持什么”和“我们建议怎样安排实验”；这三者不能代替你们设备的交付清单和现场验收。

## 一、这份 PDF 怎么读

PDF 共 29 页。前面的 EDU 操作与开发内容是标为 v1.0 的整理部分；附录 A 标注收录官方《Go2 使用手册 V4.3》。不能仅因附有官方手册，就把整理部分的网络、代码和安全结论都当作已核实的官方配置。

下面的“PDF 页码”是 PDF 阅读器的实际页序，方便直接跳转；附录里仍保留了官方手册自己的页脚页码。

## 二、核对后需要修正的地方

### 1. PDF 第 9 页的速度控制代码有接口错误

整理部分 §6.3 写的是 `client.SetVelocity(...)`。截至本次核对，官方 SDK2 Python 的 Go2 `SportClient` 类中提供的是 **`Move(vx, vy, vyaw)`**，没有该 `SetVelocity` 方法。[官方 SportClient 源码](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py)

更重要的是，PDF 中的示例在这个错误调用之前已经执行 `StandUp()`；如果随后的调用报错，代码没有异常清理，后续的 `StopMove()` 和 `StandDown()` 就可能不会运行。因此**不要直接运行该段，也不能只把方法名替换后就上实机**。速度、持续时间、看门狗、实际模式、断连后的行为和人工接管都需按本机和官方文档单独核验。

### 2. PDF 第 11 页的 Go2 RL 部署命令不能直接照搬

PDF 给出 `unitree_rl_gym` 的 `go2.yaml` 仿真与实机部署示例。2026 年 11 月 10 日检查官方仓库时，`deploy/deploy_mujoco/configs/` 和 `deploy/deploy_real/configs/` 对应目录列出的文件是 `g1.yaml`、`h1.yaml`、`h1_2.yaml`，没有 `go2.yaml`。官方仓库支持 Go2 训练，不代表 PDF 所写的 Go2 部署文件在当前版本存在；该仓库[实机部署说明](https://github.com/unitreerobotics/unitree_rl_gym/blob/main/deploy/deploy_real/README.md)目前列出 G1、H1、H1_2。

PDF 把 Isaac Lab 的 Go2 工作主要描述为社区移植；需补充：宇树已有官方 [unitree_rl_lab](https://github.com/unitreerobotics/unitree_rl_lab)，基于 Isaac Lab，README 列出支持 Go2，仓库也有 Go2 相关部署目录。真实可运行性仍需按其版本、训练资产及硬件条件核查，不能理解为已经在你们机器上验证。

### 3. IP、账户、模式和接管能力都需要现场核对

- PDF 第 3、7 页列出 `.161`、`.18` 等网络地址和示例登录方式。这些可以作为排查线索，但网络布局、地址和账户不一定就是你们设备的配置。**某个地址 ping 通或不通，单独不足以证明是否安装 Orin**，也可能受网段、网线、服务、ICMP 策略等影响。[Unitree ROS 2 官方网络示例](https://github.com/unitreerobotics/unitree_ros2)
- PDF 写“ROS_DOMAIN_ID 必须为 0”。官方示例常使用 0，实际需要与机器人和工作环境的 DDS 配置一致；不要为了套用示例随意覆盖已有环境。
- PDF 第 6 页说遥控器任何时候都能接管。**我们尚未验证你们这台的不同模式、固件、网络中断条件下的优先级**。按对应手柄／固件和现场培训确认停止及接管，阻尼模式可能使机器人失去主动支撑。
- PDF 第 5 页建议“先做固件更新”、首次试行时轻推机器狗；这些不能当作机械执行的第一步。先登记固件与设备现状，按照厂家和实验室要求决定更新；首次操作以站、走、停和正确接管为主，不需要做推扰试验。
- PDF 第 10–11 页给出低层关节参数和伪代码。当前任务是导航，不需要一开始关闭原厂运动服务或运行低层控制。以后如确实研究低层步态，应联系厂家、按对应机型与正式培训流程准备；普通用户手册也提醒上电后不要提起机器人，不能把悬吊说明当作通用操作。

## 三、结合说明书：先建立设备能力清单

| 项目 | 说明书的依据 | 本机必须确认 | 与导航研究的关系 |
|---|---|---|---|
| 前置相机 | 附录 P3 部件图 | 数据入口、分辨率、频率、标定 | 拍摄路线地标，输入视觉语言模型 |
| 深度相机 | 附录 P3–P4 的 EDU 配置图与表 | 实际是否交付、型号、RGB/深度能否读取、内参与外参 | 将视觉目标定位到三维空间、改善近距感知；不等于一定是 D435i |
| 激光雷达 | 附录 P3 标注 Unitree LiDAR L2；具体批次须核对 | 具体型号、点云、坐标系、频率 | 建图、定位、障碍物感知 |
| IMU、运动状态、关节与足端状态 | SDK / ROS 2 相关章节列出状态接口 | 哪些字段可读、频率、单位、时间戳；足端力以实际配置为准 | 姿态、运动反馈、数据同步与失败分析 |
| 机载算力 | 附录 P4 将 Orin 标为选配 | 是否安装、型号、内存、系统；也核对实验室外部 GPU | 决定模型在机载还是远端推理 |
| 高层运动接口 | SDK2 `SportClient` 和 ROS 2 运动请求 | 当前固件支持、动作响应、停止、超时、接管 | 将导航输出转换为机器狗可执行的动作 |

前置相机与深度相机可能是不同设备。App 看得到视频并不能证明已经能在 ROS 2 中获取同步、标定后的 RGB-D 数据。也不要因为某个论文用了外加 D455 或 MID-360，就先假设你们必须采购同型号设备。

## 四、面向你目前研究目标，建议怎样使用

### 第一步：手动操作与只读数据

1. 根据附录安全页、P7 和实际遥控器手册完成设备培训：正确放置、开机、绑定、站立、缓慢遥控、正常停止和关机。
2. 记录固件、网络、传感器型号、机载/远端算力；不直接重装系统或套用固定网络配置。
3. 在配置好的 Linux/ROS 2 开发环境中先查看 `ros2 topic list`，逐一确认运动状态、IMU、雷达和图像。`/sportmodestate`、`/lowstate`、`/utlidar/cloud` 是官方文档中的示例，不保证每台机器都按相同方式发布。[官方 ROS 2 接口](https://github.com/unitreerobotics/unitree_ros2)
4. 通过人工遥控采集一段路线数据，记录每个数据源的频率、时间戳和坐标系，离线回放。这样可以先验证数据链路，不依赖自主运动。

### 第二步：SLAM 与坐标导航

利用已有 Hunter 经验，建立 Go2 自己的传感器外参、机体尺寸和坐标变换，完成地图、定位和障碍物感知。先让机器人在监护下走一个短距离目标点，再逐渐扩展到走廊路线。

系统关系：**雷达 / 相机 / IMU → 建图与定位 → Nav2 规划 → 命令适配 → Go2 高层运动服务 → 状态反馈。**

Nav2 的 `/cmd_vel` 需要经过适配才能对接 Go2 运动接口；原厂发布的运动状态也不自动等同于地图中的全局定位。系统应记录超时、障碍物、人工接管和失败原因。

### 第三步：单 Agent VLN

在可靠导航上加入“出门右转，经过饮水机，到第二扇门前停下”等自然语言指令。感知模块从图像识别地标，规划模块维护任务进度，通过导航接口执行子目标；保存图像与执行日志来分析失败。

老师论文库中的 [NaVILA](https://drive.google.com/drive/folders/1w9WI5wdhZszzae3AJ580W6pIAdVNoOda) 和 [AgentVLN](https://drive.google.com/drive/folders/1QjJT00H9hmv_NOP_xWMcmsnJy1UQq9S7) 可以对照系统结构。AgentVLN 的 Go2 实验使用 D455 和 RTAB-Map，不代表你们的系统已具备完全相同的传感器与接口。[AgentVLN 论文](https://arxiv.org/html/2603.17670)

### 第四步：多 Agent 与强化学习

对一台真实 Go2，可以设计感知、规划、复核等**软件**角色。先比较相同基础模型、传感器输入和工具条件下的单 Agent 与多 Agent；再比较固定调用和事件触发调用。报告导航成功率、路径效率、错误恢复、总用时、延迟及调用量。

强化学习可以研究：

1. **Agent 调度**：什么时候重观察、查记忆、叫复核 Agent；先做规则基线，再仿真训练调度策略。
2. **导航策略**：研究动态避障或局部目标选择，优先在仿真中训练和验证。
3. **VLN 模型训练**：如研究模仿学习与强化学习结合，资源要求取决于模型和数据规模。老师库内 [JOP-VLN](https://drive.google.com/drive/folders/17maStNutA0GkD2tvRKGVIDJuZ0mq6S5I) 是可读案例。[论文](https://arxiv.org/abs/2607.13461)
4. **关节步态控制**：需要机器人动力学与低层控制，这与当前多 Agent VLN 目标不同，应作为后续独立支线。

多个软件 Agent ≠ 多台实体机器人；多个大模型角色 ≠ 多智能体强化学习。只有一台 Go2 时，可以做软件角色协作的实机实验；多机器人协作可以先在仿真中研究。

## 六、适用边界

本次只读 PDF、官方网页和仓库；没有现场确认接线、传感器、急停、网络、控制模式、程序或模型。网络地址、硬件选配、软件仓库内容可能随设备和版本变化。实际操作优先查本机交付资料及与厂家确认的安全流程。
